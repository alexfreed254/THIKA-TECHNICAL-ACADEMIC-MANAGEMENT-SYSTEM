# Project instructions

## IMPORTANT UI RULE — ALL DASHBOARDS AND PAGES

Never add explanations about how the system works to the user interface. Do not create “How it works”, “Technical Details”, “Implementation”, “Architecture”, “Developer Notes”, “Instructions”, “Walkthrough”, “Why this works”, “Next step” tip boxes, KPI gloss lines that redefine a label, migration SQL notices, coaching footers, or similar sections unless explicitly requested.

Build every dashboard and page as a real production application, not as a demonstration or tutorial. The UI should contain only information and controls that an actual end user needs (titles, status, numbers, actions).

Do not describe your coding process. Do not expose implementation details. Do not add explanatory cards simply to demonstrate functionality. If a feature is self-explanatory, leave it self-explanatory.

Final result = clean production UI only.
